# Проверка усиления пользовательских сессий

Ветка `fix/backend-without-docker-socket`. Дата: 27 ноября 2026.
MFA не включалась. Проверка выполнялась локально, production не обновлялся.

## Реализованный контракт

Пользовательский API использует HttpOnly cookie вместо Bearer/localStorage.
Изменения требуют точный настроенный Origin и `X-Tracker-Request: 1`.
Вход и восстановление сессии проходят через `/auth/google` и `/auth/me`;
выход удаляет cookie на сервере, выход везде атомарно отзывает версии токенов.
Удаление допуска и блокировка немедленно закрывают доступ; разблокировка
не возвращает старые токены. WebSocket проверяет cookie/Origin, срок токена
и отзыв. Приватный кэш очищается при смене входа; вкладки синхронизируются
без передачи секретов. Миграция `f8c1a6d2b940` отзывает прежние токены,
не затрагивая задачи LLM.

Backend больше не получает Docker socket. Контейнеры собирает воркер;
API читает ограниченный по времени снимок из Redis. Отсутствующий,
просроченный или повреждённый снимок даёт 503.

Негативные сценарии включают отсутствие/подделку/истечение cookie,
отказ старому Bearer, удаление допуска и невозможность восстановления
прежней сессии, запрет чужого/пустого/null Origin и отсутствие защитного
заголовка, запрет чужого WS Origin, deadline WS при непрерывном выводе
и освобождение Redis-подписки. Миграция проверяется на отдельной временной БД,
включая downgrade без уменьшения версии. Frontend проверяет поздний 401
после нового входа и сохранение текущей сессии/кэша при ошибке выхода.

## Проверка в настоящем браузере

Chrome в headless-режиме, настоящий FastAPI, PostgreSQL в отдельной тестовой
БД и Redis. Production-настройки cookie проверены на локальном HTTPS
с тестовым сертификатом; dev-настройки — на отдельном HTTP-порту.
Подменены только Google Identity Services и проверка Google id_token:
реальный Google-аккаунт и production-секреты не использовались.

На обоих стендах успешно выполнены:

1. Кнопка Google → вход → cookie → защищённый экран.
2. Проверка HttpOnly, Secure (только HTTPS), SameSite=Lax, Path=/;
   cookie недоступна из `document.cookie`, токена нет в localStorage.
3. Перезагрузка страницы и восстановление через `/auth/me`.
4. Отказ logout без защитного заголовка с сохранением текущего доступа.
5. Обычный выход через UI, удаление cookie и переход на вход в двух вкладках.
6. Выход на всех устройствах через UI; повтор скопированной cookie даёт 401.
7. Попытка logout со стороннего Origin из другого браузерного документа
   не завершает действующую сессию.

Дополнительно на HTTPS проверен настоящий WebSocket: cookie handshake без
первого auth-сообщения, получение статуса задачи, затем `/auth/logout-all`;
соединение закрывается с 4401 в пределах периода перепроверки (~10 секунд).

## Выкладка

Изменения пока локальные в текущей ветке. Backend и frontend нужно обновлять
вместе; после миграции пользователю потребуется повторный Google-вход.
Порядок настройки Origin, dev-режим и ограничения отката описаны в
`docs/deployment.md`. LLM-пайплайны миграция пользовательских сессий не меняет.

В полном прогоне остаются предупреждения существующей тестовой обвязки Celery
(`task_always_eager` для `send_task`); production build предупреждает о размере
JS bundle. Изменения авторизации не добавляют новых зависимостей.
