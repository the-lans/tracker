# Метрики агентных сессий

Пока Tracker не использует отдельный Prometheus/OpenTelemetry-сборщик. Для
диагностики Claude Agent SDK применяются структурированные события текущего
логгера. Они сохраняются вместе с обычными логами воркера и связываются с
задачей через `task_id`.

## Итог хода

События `session_connected` и `session_disconnected` содержат `duration_ms` —
время запуска/остановки CLI-процесса.

Событие `session_query_finished` содержит:

| Поле | Смысл |
| --- | --- |
| `duration_ms` | Полное время от отправки промпта до `ResultMessage`. |
| `time_to_first_event_ms` | Время до первого события SDK. `null` означает, что SDK не прислал ни одного события. |
| `tool_call_count` | Число вызовов инструментов в ходе, включая MCP, Bash и встроенные инструменты. |
| `subagent_call_count` | Число вызовов `Agent` или `Task`. |
| `tool_error_count` | Число результатов инструментов с ошибкой. |
| `tool_duration_total_ms` | Суммарная длительность полученных результатов инструментов. |
| `tool_duration_max_ms` | Максимальная длительность одного полученного результата инструмента. |
| `is_error` | Признак ошибки результата SDK. |
| `assistant_error` | Тип ошибки ассистента, если SDK его сообщил. |

При исключении SDK или отмене хода событие всё равно записывается со статусом
`error` или `cancelled`, поэтому зависшие и прерванные ходы не теряются из
наблюдаемости.

Эти поля позволяют отличить медленный ответ модели от долгого MCP-вызова и
увидеть незапланированное делегирование субагентам.

## Диагностический режим

При `CLAUDE_DIAGNOSTICS=true` дополнительно записываются события
`session_tool_started` с именем инструмента и сокращёнными аргументами.

- аргументы ограничены 200 символами;
- поля `token`, `secret`, `password` и `key` маскируются;
- записывается не более 50 tool-событий на ход;
- stderr Claude CLI записывается отдельным событием `claude_cli_stderr`;
- `Agent`, `Task`, `Bash` и `ListAgents` запрещены;
- число ходов ограничено `CLAUDE_DIAGNOSTICS_MAX_TURNS` (по умолчанию 20).

Диагностический режим выключен по умолчанию. Он предназначен для короткого
контролируемого запуска и не должен постоянно включаться на production.

Для worker-контейнеров Compose ограничивает Docker logs: один файл — до 50 МБ,
хранится не более трёх файлов. Поэтому временное включение диагностики не может
бесконечно занять диск Docker-логами. При необходимости длительного сбора нужно
выгружать логи во внешнюю систему, а не увеличивать локальный лимит.

## Поиск зависаний

Для задачи используйте фильтр логов по `task_id` и сопоставляйте:

1. `session_query_started` без последующего `session_query_finished` — ход ещё
   выполняется или был прерван;
2. большое `time_to_first_event_ms` — задержка до первого события SDK;
3. большое `duration_ms` при большом `tool_call_count` — широкий обход;
4. `subagent_call_count > 0` — модель использовала делегирование;
5. последнее `session_tool_started` — кандидат на зависший инструмент.

Если SDK присылает `UserMessage` с `ToolResultBlock`, длительности инструментов
рассчитываются по идентификатору вызова. Если версия CLI не пересылает такие
сообщения, Tracker включает CLI-флаг `replay-user-messages`. Счётчики вызовов
всё равно работают, а поля длительности остаются `null`/`0` и не должны
интерпретироваться как быстрый вызов.

Подробные события не должны использоваться для хранения содержимого промптов,
ответов или секретов.
