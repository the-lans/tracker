# Развёртывание Tracker

Используй этот навык для запроса развернуть Tracker, подготовить его сервер,
настроить автоматические обновления или сменить домен установленного Tracker.
Вопрос «как развернуть» без поручения выполнить действия означает консультацию.

1. Найди корень репозитория. Прочитай [docs/deployment.md](../../../docs/deployment.md)
   — общий сценарий для Claude и Codex. Сначала прочитай разделы 1–2, затем
   для первой установки разделы 3–7, для обновления раздел 9, для смены домена
   раздел 10; раздел 8 нужен при настройке CI/CD. Проверки результата — раздел 7.
   Проверь актуальные
   `deploy/install.sh`, `deploy/ci_deploy.sh`, `.env.example` и Compose/workflow-файлы
   перед выполнением соответствующего этапа.
2. Собери параметры из запроса и доступного контекста. Определи, нужна первая
   установка, обновление, смена домена или только настройка CI/CD. Проведи
   проверки состояния из документа до изменения сервера. Основной целевой
   дистрибутив — AlmaLinux/Rocky Linux; для Ubuntu/Debian используй ветку apt.
3. Выполняй разрешённую работу сам через доступные SSH, shell и GitHub-инструменты.
   Не превращай поручение установить в перечень действий для пользователя.
   Если нужен ручной шаг, используй интерактивный сценарий документа: конкретное
   место в панели, одно действие, ожидаемый результат, затем самостоятельная
   проверка. Продолжай независимые этапы, пока ждёшь ответа.
4. Используй домен и доступы текущего запроса. Не переноси адреса, email, ключи,
   размеры swap или настройки DNS из прежних установок как значения по умолчанию.
   Не печатай секреты и не подставляй их в shell-команды; передавай через
   защищённый ввод/файлы. Сохраняй существующие данные и ключи `.env`.
5. Следуй выбранному маршруту документа до проверенного результата. Не считай
   `/api/health` достаточной проверкой: нужны UI/OAuth-конфигурация (origin, а для
   Google Calendar — redirect URI, Calendar API и право `calendar.readonly`), оба воркера,
   beat, HTTPS, сетевые порты и бэкап. Подключение Google/LLM завершает пользователь
   в браузере, если требуется его сессия.
6. Сообщи URL, развёрнутый коммит и локальные отличия, выполненные проверки,
   состояние CI/CD и точные оставшиеся ручные шаги. Не заявляй о проверке
   входа, S3 или восстановления, если они не выполнялись.

Обнаружение навыка само по себе не разрешает деплой. Поручение пользователя
установить/обновить на названном сервере разрешает обычные действия этого
сценария; повторное подтверждение каждого шага не нужно. Согласуй только
выход за поручение: замену существующей установки, удаление данных, перенос
всей DNS-зоны или принудительное прерывание живых задач, если это ещё не разрешено.
