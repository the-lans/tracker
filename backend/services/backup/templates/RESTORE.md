# Восстановление трекера из резервной копии

Здесь лежат зашифрованные копии трекера задач: `tracker-backup-<время UTC>.tar.gpg`.
Время в имени — момент снятия копии; самая свежая копия — последняя по имени.
Каждая копия полная: после восстановления трекер на новом сервере работает так же,
как на прежнем, — с теми же задачами, историей сессий агента, файлами, репозиториями
(включая незапушенные коммиты), LLM-аккаунтами, ключом SFTP и настройками.

- Хранилище: `@ENDPOINT@`, бакет `@BUCKET@`, папка `@FOLDER@`.
- Ключи доступа к S3 и пароль шифрования здесь не записаны: их хранит администратор
  трекера. Без пароля шифрования копию не расшифровать.

## Что внутри копии

Архив `tracker-backup-<время>.tar.gpg` зашифрован `gpg --symmetric` (AES-256).
Внутри — каталог `tracker-backup-<время>/`:

| Файл | Что это |
|---|---|
| `.env` | Настройки сервера: домен, ключи шифрования секретов, пароли БД и Redis, Google OAuth, VAPID |
| `tracker-<время>.sql.gz` | Дамп всей базы PostgreSQL |
| `task_repos.tar.gz` | Рабочие копии репозиториев задач, целиком с `.git` |
| `user_files.tar.gz` | Файлы и артефакты задач |
| `log_archive.tar.gz` | Архив старой истории выполнения |
| `claude_sessions.tar.gz` | История диалогов агента и настройки сессий задач |
| `cliproxy_data.tar.gz` | Учётки LLM-прокси с токенами входа провайдеров |
| `claude_accounts.tar.gz` | Каталоги LLM-аккаунтов прежней версии (если были) |
| `sftp_host_keys.tar.gz` | Ключ хоста SFTP — отпечаток сервера не меняется |
| `manifest.json` | Коммит трекера, время, состав, число строк каждой таблицы, пропущенные файлы |
| `SHA256SUMS` | Контрольные суммы всех файлов копии |
| `restore.sh`, `RESTORE.md` | Скрипт и эта инструкция |

Код трекера и образы Docker в копию не входят: `install.sh` берёт их из GitHub на том
коммите, на котором снята копия (`tracker_commit` в `manifest.json`).

## Требования к новому серверу

- Ubuntu 22.04+ или Debian 12+, x86_64 или arm64; доступ root или `sudo`.
- Свободное место — не меньше трёх размеров копии (архив, распакованные файлы и данные
  в Docker), оперативная память — как у прежнего сервера (от 4 ГБ).
- Открытые порты 80 и 443 (HTTPS) и порт SFTP из `.env` (`SFTP_PORT`, по умолчанию 2222).
- Пакеты для начала: `gnupg`, `curl`, `ca-certificates`. Docker, Git и остальное
  поставит `install.sh`.
- Средство скачивания из S3: AWS CLI (`aws`), `s3cmd`, `rclone` или веб-консоль
  хранилища.

## Восстановление

1. Подготовьте сервер:

   ```bash
   sudo apt-get update && sudo apt-get install -y gnupg curl ca-certificates awscli
   ```

2. Скачайте последнюю копию и скрипт (подставьте ключи доступа к S3):

   ```bash
   export AWS_ACCESS_KEY_ID=<ключ доступа> AWS_SECRET_ACCESS_KEY=<секретный ключ>
   export AWS_DEFAULT_REGION=@REGION@
   aws --endpoint-url @ENDPOINT@ s3 ls s3://@BUCKET@/@FOLDER@/
   aws --endpoint-url @ENDPOINT@ s3 cp s3://@BUCKET@/@FOLDER@/<tracker-backup-...tar.gpg> .
   aws --endpoint-url @ENDPOINT@ s3 cp s3://@BUCKET@/@FOLDER@/restore.sh .
   ```

3. Восстановите трекер — скрипт спросит пароль шифрования:

   ```bash
   sudo bash restore.sh tracker-backup-<время>.tar.gpg
   ```

   Скрипт расшифрует копию, проверит контрольные суммы, скачает `install.sh` того же
   коммита и запустит `install.sh --restore <каталог> --ref <коммит>`: установка
   Docker, сборка образов, загрузка дампа, распаковка данных, миграции, запуск
   сервисов. Займёт от 10 минут до часа.

4. Переключите DNS домена (`DOMAIN` в `.env`) на новый сервер. Сертификат HTTPS
   выпустится сам, когда DNS укажет на сервер. Если домен меняется — поменяйте
   `DOMAIN` в `/opt/tracker/.env` и Authorized JavaScript origins OAuth-клиента в
   Google Cloud Console (`https://<домен>`), затем
   `cd /opt/tracker && docker compose up -d`.

5. Автоматическое развёртывание из GitHub (если было) настройте заново по
   `docs/deployment.md` репозитория: ключ CI в копию не входит.

## Проверка после восстановления

- `https://<домен>/api/health` отвечает `{"status": "ok", "version": "<коммит>"}`;
  коммит совпадает с `tracker_commit` из `manifest.json`.
- Вход прежним Google-аккаунтом администратора; на дашборде — прежние задачи.
- «LLM-аккаунты»: аккаунты в статусе «активен». Если провайдер отозвал токены —
  «Войти» у аккаунта.
- Задачи, которые выполнялись в момент копии, — в статусе «Ошибка»: продолжите их кнопкой
  «Перезапустить с текущей ноды».
- «Администрирование → Системные настройки → Резервное копирование»: включено, и
  ночью появится новая копия.

## Только распаковать (без восстановления сервера)

```bash
bash restore.sh tracker-backup-<время>.tar.gpg --extract-only ./restored
```

Файлы копии — в `./restored/tracker-backup-<время>/`, данные каждого volume — в
`./restored/volumes/<имя>/`. Дамп БД читается так:
`gzip -dc ./restored/tracker-backup-*/tracker-*.sql.gz | less`.

## Для LLM-агента

Выполняй шаги по порядку и проверяй ожидаемый результат; при расхождении остановись и
сообщи человеку вывод команды. Не выводи в ответ содержимое `.env`, ключи S3 и пароль.

1. `uname -m && . /etc/os-release && echo "$ID $VERSION_ID"` — ожидается x86_64 или
   aarch64 и Ubuntu ≥ 22.04 или Debian ≥ 12.
2. `df -h / && free -g` — свободно не меньше трёх размеров копии, памяти от 4 ГБ.
3. Установи пакеты из шага 1 «Восстановления». Ожидается: `gpg --version` и
   `aws --version` печатают версии.
4. Попроси у человека ключи S3 и пароль шифрования. Пароль запиши в файл с правами
   600: `install -m 600 /dev/null /root/backup-passphrase && cat > /root/backup-passphrase`.
5. Выполни шаг 2 «Восстановления». Ожидается: `ls -l tracker-backup-*.tar.gpg restore.sh`
   показывает оба файла, размер копии совпадает с выводом `aws s3 ls`.
6. `sudo BACKUP_PASSPHRASE_FILE=/root/backup-passphrase bash restore.sh tracker-backup-<время>.tar.gpg`.
   Ожидается: строки `: OK` у каждого файла при проверке контрольных сумм и в конце
   `Восстановление завершено`. Ошибка `decryption failed` — неверный пароль;
   `FAILED` у контрольной суммы — повреждённая копия, возьми предыдущую по имени.
7. `curl -fsS https://<домен>/api/health` (или `curl -fsSk --resolve <домен>:443:127.0.0.1 https://<домен>/api/health`,
   пока DNS не переключён) — ожидается `"status":"ok"` и `version`, равный
   `tracker_commit` из `manifest.json`.
8. `cd /opt/tracker && docker compose ps` — все сервисы `running`/`healthy`, кроме
   одноразовых `cliproxy-init`.
9. Удали файл пароля: `shred -u /root/backup-passphrase`. Сообщи человеку про шаги 4 и 5
   «Восстановления» (DNS, OAuth, CI).
